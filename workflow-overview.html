System Storage Monitor

End-to-end workflow overview · implementation-based · detailed Mermaid flows and step table in WORKFLOW.md

Detailed workflow
  1. Start the services. Configure the environment, start the Node API, PostgreSQL, and Python watcher. If the database is unavailable, API startup fails; fix the connection and restart.
  2. Sign in and authorize. The API validates the account, session, role, and computer access. Missing or invalid access returns 401 or 403; sign in again or ask an administrator to grant access.
  3. Watch storage. The Python watcher observes configured roots, ignores temporary files, waits for stable file metadata, then appends events to JSONL.
  4. Refresh the dashboard. The browser polls the API every five seconds and displays authorized drive and file data. API errors appear in the dashboard and polling retries.
  5. Optional daily report. A Windows scheduled task runs at 9:00 AM local time, captures the drive view, and emails it through SMTP. Preview saves locally; capture or SMTP failures are reported by the task.
